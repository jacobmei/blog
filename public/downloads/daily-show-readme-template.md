# <節目名稱>：每天的製作流程

> 這份 README 是寫給 AI（例如 Claude Code）看的工作說明。每次開工，跟它說「照 README 做 <日期或月份>」，
> 它會讀這份檔案照做；做完再把新學到的事寫回來。改成你自己的節目時，把角括號 `< >` 的地方換掉。

## 節目規格

- 畫面比例：<9:16 直式／16:9 橫式>，片長約 <60> 秒
- 結構：<片頭（封面卡）→ 主體（經文、內文、默想）→ 片尾（署名卡）>
- 聲音：<旁白用誰的聲音、用什麼工具產生>
- 背景畫面：<每天換的畫面是什麼，例如天空、水面；由哪個 AI 影片工具生成>
- 配樂：<放在哪個資料夾、每天怎麼輪替、要不要署名>

- 授權：<聲音是誰的、有沒有同意；配樂的授權與署名方式；上稿時要不要標示 AI 生成>

## 給 AI 的規則

1. 原文疑似有錯字時，**列出來問我**，不要自己改原文。
2. 每一步做完都要有檔案留下來（見下方「每天的資料夾」），中斷了可以從缺的那一步接著做。
3. 判斷不了的事停下來問，不要猜。
4. 做完一批，把新踩到的問題和解法寫進最下面的「已做過」。
5. 要改流程時，先寫進「下次開工前」，下一次開工第一件事就是處理它。
6. 需要登入的網站如果登入過期，停下來請我自己登入，不要代我輸入密碼。
7. 說明欄需要署名的素材（例如 CC BY 的配樂），產生 `post.txt` 時自動加上。

## 每天的資料夾

每天一個資料夾，名稱用日期 `YYYYMMDD/`：

| 檔案 | 內容 | 哪一步產生 |
|---|---|---|
| `source.txt` | 當天原文 | 1 |
| `day.json` | 當天的設定：日期、出處、要上畫面的字、旁白句子、默想問題、背景主題 | 1 |
| `tts/voice.wav` | 接好的旁白（同一個資料夾留每個版本的分數） | 2 |
| `bg/` | 背景影片片段 | 3 |
| `<節目名>_<日期>.mp4` | 組好的片 | 4 |
| `post.txt` | 上稿用的標題與說明（含配樂署名） | 4 |
| `audio.mp3` | 旁白加配樂的音訊版（要上 Podcast 才需要） | 4 |
| `published.json` | 上稿紀錄（有這個檔就不要重複上傳） | 5 |

共用素材（片頭卡、片尾卡、字型、配樂、聲音參考檔）放 `_fixed/`。

## 一次做一整個月

1. **文字**：把整個月的原文切成每天的 `source.txt`，產生每天的 `day.json`。疑似錯字整理成一張表給我確認。
2. **旁白**（最花時間，先開始、背景跑）：每句產生 3 個版本，用語音辨識檢查字有沒有唸對，挑最好的一個接起來。
   只把「每個版本都唸錯同一個字」或「漏了句子」的地方列給我聽。
3. **背景畫面**（跟旁白同時跑）：照當月主題寫每天的提示詞，送到影片工具生成，收回來後抽幾格畫面檢查。
   只擋明顯不該出現的東西：<例如建築、文字、人、動物>。小瑕疵直接收。
4. **組裝**：旁白好了就組那一天：片頭、背景、字卡、旁白、配樂。字卡時間跟著旁白走。
   組完檢查片長、音量、幾個時間點的畫面（字有沒有出現、有沒有被蓋住）。
5. **上稿**：<平台>排定每天 <06:00> 公開，標題和說明用 `post.txt`。上傳後寫 `published.json`。
   用 AI 生成或克隆的聲音，<YouTube> 要勾選「合成內容」。上傳完對帳一次：每一天都有排定、沒有漏也沒有重複。
6. **備份**：只備份重做不出來的東西（原文、`day.json`、聲音參考檔、定稿素材、這份 README）。

## 字詞對照表

`_fixed/lexicon.json`，越用越完整：

- `tts`：旁白產生前先換字（例如 AI 唸不準的罕用字，改成同音的常用字）
- `card`：字卡換字（字型裡沒有的字）
- `typo`：原文常見錯字，我確認過的標記起來
- `asr_ok`：語音辨識常聽錯、但其實唸對的詞，以後不再報
